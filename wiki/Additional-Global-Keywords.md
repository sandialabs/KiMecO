# Additional Global Keywords

These settings are still part of default_settings and therefore can appear in runtime settings if present in input JSON.

| Keyword | Default value | Description |
|---|---|---|
| scratch_base | dynamic path under /scratch/<user>/kmo/... | Base directory for simulation work. Generated dynamically at runtime import. |
| project_name | "KMO_Project" | Work directory/project folder name. |
| log_level | 20 (INFO) | Logging verbosity. |
| rc_software | "mess" | Master equation software backend selector. Currently the only other supported Master Equation backend. |
| use_automech | false | Optional rate-coefficient path. When false, KiMecO runs the standard single-pass MESS. When true, KiMecO emits a per-PES Python driver that uses automech's `mess_io` API to run MESS pass 1 and then checks the pass-1 output for well merging (missing rate coefficients); the extended pass 2 with automatic WellExtension well-lumping is run **only when well merging is detected**, otherwise the pass-1 result is kept as the final output. The automech path writes the same pressure grid as the normal pipeline: the `rc_pres` values are passed through unchanged and declared as `PressureList[bar]`, with no unit conversion. It also mirrors the normal pipeline's header hyperparameters: `CalculationMethod`, `ModelEnergyLimit`, `ExcessEnergyOverTemperature`, `ChemicalEigenvalueMax`, `ExponentCutoff`, `EnergyStepOverTemperature`, `WellReductionThreshold` and `WellExtension` (kept through pass 2) are forwarded from the parsed MESS input when present (mess_io defaults otherwise; `ModelEnergyLimit`, `WellReductionThreshold`, `WellExtension` and the `HotEnergies` block per PES, the energies of the latter shifted with the perturbation of their well), the PED and microcanonical-rate outputs, the Lennard-Jones pair and `Masses[amu]` line of each PES, the `RigidRotor` `SymmetryFactor` of wells, fragments and saddle-point transition states, and hindered rotors declared on barrierless `Core Rotd` transition states (with their embedded geometry) are all honoured (see the Extra Notes section for the remaining driver assumptions). Requires `automech` (`autoio`/`mess_io`) installed in both the run and job environments, e.g. via `pip install kimeco[automech]` (or `pip install -e .[automech]` from source) after pre-installing `autoio`/`autochem` from GitHub as described in the installation instructions, since they are not published on PyPI; the run is cancelled early with a clear message if it is missing. The emitted driver also imports KiMecO itself, so `kimeco` must be importable in the job (compute-node) environment too. In the `kmo_start` GUI this appears under the "Rate Coefficients" category. |
| prompt_reactions | false | Prompt (non-thermal) reactions: products formed hot (`PEDSpecies` of one PES) feed the `HotEnergies` wells of another PES. Allowed values: true or false. Requires `use_automech=true`, `mechanalyzer` (AutoMech, not on PyPI, installed by hand, see the installation instructions) importable in every process of the run, and MESS inputs that link at least one PES with `PEDSpecies` to a PES with `HotEnergies` (a product of a `PEDSpecies` pair must match a `HotEnergies` species of another PES; a linked PES with `PEDSpecies` must give all its `MicroEner` outputs). KiMecO cancels the run before submitting any job when a requirement is missing (settings checks and MESS-input reading). A PES with `PEDSpecies` that is not linked only logs a warning. In this mode every PES driver always runs the extended MESS pass 2 (with well-lumping), whether or not wells merge, so the rates of every PES, including abstraction PESs, come from pass 2. Also see the Extra Notes section. |
| prompt_ped_model | "rovib_dos" | Energy-partition model of mechanalyzer for the hot products. Allowed values: `equip_simple`, `equip_phi`, `rovib_dos`, `beta_phi1a`, `beta_phi2a`, `beta_phi3a`, `thermal`, `fne`. Checked only when `prompt_reactions` is true; any other string cancels the run. |
| prompt_bf_threshold | 0.01 | Branching-fraction threshold, a number in [0, 1): a prompt product is kept when its branching fraction reaches the threshold at one (T, P) point at least. Checked only when `prompt_reactions` is true; a value outside [0, 1) (or not a number) cancels the run. |
| restart | "default" | Restart strategy for database/table handling. Only other possible value is "rescore". Will not produce new models but will rescore existing ones. Be sure you know what you're doing if changing this option. Backing up your databases ahead is recommended as the scores will be overwritten.|
| db_user | current username | Database user name. |
| db_host | "127.0.0.1" | Database host address. |
| threads | 1 | Main-process I/O thread count. Increase to run multiple NM instances during Nelder-Mead Swarm optimization. This option does not require MPI.|
